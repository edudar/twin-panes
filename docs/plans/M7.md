# M7 plan: preview pane and hex integration

_Status: approved 2026-11-26; ready to commit (step 1)._

## Context

M6 left two panels with tabs, a sidebar, window restoration, path completion,
multi-selection, the function-key bar, and file operations. Today `F3` (`browserView`),
`F4` (`browserEdit`), and Return on a file all open a `HexEditorItem` and create an
`EditorSession`. `AppDelegate.show(_:in:)` inserts new tabs into `item.preferredSlot`
(`.leftPanel`) rather than the active panel, and there is neither a right preview pane nor
a read-only `QuickViewItem`.

PLAN.md §6 (M7) and §4.7–§4.8 call for:
- a collapsible right preview pane with `QLPreviewView`, file metadata (size, dates,
  permissions, extended attributes), pinning, and a hex view for types Quick Look cannot
  render;
- a viewer factory protocol in `WorkspaceKit`, backed by `HexViewKit` and injected by the
  `TwinPanes` app target so `BrowserKit` never imports `HexViewKit` or `EditorKit` (§4);
- `QuickViewItem` (`F3` / `⌘Y` / `⌃⌘V` in the opposite panel, `⇧F3` / `⇧⌃⌘V` in the
  active panel): a read-only `ByteSource` that never creates an `EditorSession`, shows a
  live snapshot with an unsaved-edits marker when `SessionRegistry` already holds a dirty
  session for that file, and lets `F4` (`Edit`) open or focus the real `HexEditorItem`;
- `F4` (`⌃⌘E`) from the browser opening the hex editor tab in the active panel for regular
  files (D14).

Items from PLAN.md §9 relevant here:
- *Two tabs on one session* (from M3b): M7 never creates a second `HexEditorItem` for one
  file; read-only viewers observe an existing `EditorSession` weakly and read immutable
  `EditSnapshot`s, leaving multi-view editing for M11.
- *Keyboard shortcuts* (from `docs/reviews/Shortcuts.md`): primary shortcuts follow Finder
  (`⌘Y` View, `⇧⌘P` Show Preview), with `⌃⌘` + letter and NC F-keys as secondary layers.

**Done when:** the hex editor is reachable entirely from the file manager, the preview
pane and quick view follow selection smoothly without stalling on 1,000-file sweeps, and
moving the cursor through 1,000 files in quick view creates zero `EditorSession`s and leaks
no file descriptors. Proven in the smoke test on real files.

## Decisions

### D-a: cross-kit viewer boundary (`WorkspaceKit` + `HexViewKit`)

- `BrowserKit` never imports `HexViewKit` or `EditorKit` (§4). `WorkspaceKit` defines
  `HexViewerStyle` (`.regular`, `.compact`), `HexPreviewing` (`viewController`,
  `showsUnsavedEdits`, `onStateChange`, `show(_:scope:)`), and `HexViewerFactory`
  (`makeHexViewer(style:)`).
- `HexViewKit` (which already imports `WorkspaceKit` and `TwinPanesCore`) implements
  `ReadOnlyHexViewController` conforming to `HexPreviewing` and `SessionHexViewerFactory`
  conforming to `HexViewerFactory`, taking `SessionRegistry` and an injectable
  `CloudDownloads` seam (D55).
- `TwinPanes.xcodeproj` links `HexViewKit` explicitly as a product dependency (previously
  transitive through `EditorKit`), and `AppDelegate` injects one `SessionHexViewerFactory`
  into every window's preview pane and every `QuickViewItem`.

### D-b: read-only hex viewer and live session sync (`HexViewKit` + `TwinPanesCore`)

- `ReadOnlyHexViewController` wraps `HexView` in strictly read-only mode (`HexViewDelegate`
  defaults `overwrite` to `false`), using `.autoFit` bytes per row (13 pt monospaced font
  for `.regular` in QuickView, 11 pt for `.compact` in the preview pane) and a bounded
  `ByteSource` page cache (`pageCapacity: 32`, ~2 MiB) so viewing a 4 GB file stays O(1) and
  light on memory. Selection copy uses `readSequential` (`readForCopy`) so copying never
  evicts cached pages.
- **Never creates a session:** on `show(url, scope:)`, it checks `sessions.session(for: url)`
  first and never calls `sessions.open`.
  - When a live `EditorSession` exists, the viewer observes it **weakly** (never extending
    its lifetime), displays `session.snapshot` (with `modifiedRanges` highlighted), and
    sets `showsUnsavedEdits = session.isDirty`. Edits, saves, reverts, and reloads update
    the view live.
  - Otherwise, on a serial background queue guarded by a monotonic generation counter (so
    rapid retargeting drops superseded opens before touching disk), it checks
    `CloudDownloads.isDataless(url)` first so arrowing past cloud files never triggers a
    surprise iCloud download (showing a placeholder with a Download button instead, D55),
    then opens `ByteSource(url:pageCapacity:32)` with `SecurityScope` retained.
- Add `EditorSession.Change.closed` (emitted by `EditorSession.close()`, splitting internal
  `closeFolder()` for reload paths so reloads don't look like closes) and
  `SessionRegistry.observe(_:_:)` for newly opened or adopted sessions:
  - if an editor tab opens and edits a file currently shown in QuickView or the preview
    pane, the viewer attaches to that session and updates live;
  - if that editor tab closes, `.closed` detaches the viewer and reloads a fresh read-only
    `ByteSource` from disk, clearing the unsaved-edits marker.
- Non-regular files, missing files, and read errors show an inline secondary-label message,
  never a modal alert sheet.

### D-c: preview classification and file metadata (`TwinPanesCore`)

- `QLPreviewView` does not report when Quick Look falls back to a generic file icon, so
  `PreviewClassifier` (pure, deterministic, in `TwinPanesCore`) selects the default
  `PreviewMode` (`.quickLook` vs `.hex`) from `UTType` and file state:
  - folders, packages, and dataless iCloud files -> `.quickLook` (or placeholder; never
    opens raw bytes);
  - a regular file with an open dirty `EditorSession` -> `.hex`, so unsaved edits appear
    immediately with the unsaved-edits banner;
  - a regular file conforming to a Quick Look-renderable type (`.image`, `.pdf`,
    `.audiovisualContent`, `.text`, `.propertyList`, `.rtf`, `.rtfd`, `.font`,
    `.threeDContent`, `.webArchive`, `.calendarEvent`, `.vCard`, `.emailMessage`, and
    iWork/Office/OpenDocument types) -> `.quickLook`;
  - all other regular files (`.data`, dynamic types, executables, disk images, archives,
    unknown binary extensions) -> `.hex`.
- Both the preview pane and QuickView offer a `Quick Look | Hex` segmented control for
  regular files so the user can override the default for the current file (resetting to the
  classifier's default when moving to another file).
- `FileMetadata` (`TwinPanesCore`, `Sendable`) reads strictly O(1) metadata off the main
  actor (`lstat`, `readlink`, `getpwuid_r`/`getgrgid_r`, `listxattr` + `getxattr`
  size-only with `XATTR_NOFOLLOW`, capped at 64 attributes): logical size, allocated disk
  size, created/modified/accessed dates, POSIX permissions (`rw-r--r-- (0644)`),
  owner/group, BSD flags (locked, hidden, dataless), hard-link count (shown when > 1),
  symlink target, and extended attribute names with byte sizes. It never enumerates
  folder contents.

### D-d: collapsible right preview pane (`WorkspaceKit` + `BrowserKit`)

- `MainFrameViewController` hosts an optional trailing `previewPane: NSViewController?`
  inside its existing `SidebarSplitViewController` as a **regular trailing
  `NSSplitViewItem`** -- explicitly **not**
  `NSSplitViewItem(inspectorWithViewController:)`, because `NSSplitViewController` handles
  and validates `toggleInspector:` whenever an inspector item is present, which would
  collide with the hex editor's Data Inspector (`HexEditorActions.toggleInspector:`, `⌥⌘I`).
- Hidden by default (`wantsPreviewShown = false`), default width 260 pt (min 220, max 480).
  Default new window content size increases from `900x600` to `1120x700` so Sidebar (180)
  + Left (340) + Right (340) + Preview (260) fit without constraint pressure.
- Toggled via `View › Show/Hide Preview` (`⇧⌘P`, Finder's shortcut; action
  `togglePreviewPane:`) and a trailing `sidebar.trailing` toolbar item in `MainToolbar`.
- Visibility and width save per window in `WindowState` as optional fields (`previewShown`,
  `previewWidth`), keeping `WindowState.currentVersion == 1` backward-compatible (D23).
- `PreviewPaneViewController` (in `BrowserKit`) has a header bar (`Quick Look | Hex` and
  a Pin toggle), an optional unsaved-edits banner (with a "Show Hex" button when in Quick
  Look mode), and a vertical `NSSplitView` holding the preview area (`QLPreviewView` with
  `.compact` style wrapped in `QuickLookHostView`, a lazy `HexPreviewing`, or a
  placeholder) above a scrollable metadata view.
- **Idle when collapsed:** collapsing the pane notifies
  `PreviewPaneViewController.setActive(false)`, clearing `QLPreviewView.previewItem`,
  releasing `ByteSource` and `SecurityScope`, and skipping selection updates until shown
  again. `QLPreviewView` sets `shouldCloseWithWindow = false` and calls `close()`
  explicitly in `tearDown()` (called from `MainWindowController.windowWillClose`) to avoid
  leaks.
- **Debounced retargeting:** selection updates coalesce over a short delay (40 ms,
  injectable as `.zero` in tests) with a generation counter, so sweeping across 1,000 files
  never floods Quick Look XPC or stalls the main thread. Multi-selection shows a summary
  ("N items selected" plus total file size from `selectedEntries`); `".."` or an empty
  selection shows "No Selection". Pinning freezes the displayed item and catches up
  immediately when unpinned.

### D-e: `QuickViewItem` -- F3 opposite-panel and ⇧F3 same-panel (`BrowserKit` + `WorkspaceKit`)

- `QuickViewItem` (`ItemKind.quickView`, `isDirty = false`, `restorableState = nil`, eye
  SF Symbol icon, title equal to filename or `"Quick View"`) is a `WorkspaceItem` in
  `BrowserKit`.
- `MainFrameLayout` gains `insertInBackground(_:in:at:)` and `selectInBackground(_:)` so
  opening or revealing a QuickView tab in the opposite panel never steals `activePanel` or
  keyboard focus from the browser (Far Ctrl+Q style, §4.8, D9).
- **F3 / `⌘Y` / `⌃⌘V` (`browser.view`):** opens (or reuses an existing unpinned following)
  `QuickViewItem` in the opposite panel without changing `activePanel`. While unpinned,
  moving the cursor in the source browser retargets it live (via
  `BrowserItem.onSelectionChange`, without rebuilding tabs). Pressing F3 again while that
  following `QuickViewItem` is already frontmost in the opposite panel toggles it closed;
  if it was behind another tab, F3 brings it forward retargeted. Dragging or moving a
  following `QuickViewItem` into its source browser's panel pins it automatically.
- **⇧F3 / `⇧⌃⌘V` (`browser.viewInSamePanel`):** opens a standalone (pinned)
  `QuickViewItem` in the active panel and focuses it so the user can scroll, copy, or zoom
  immediately; `⌘W` closes it back to the browser.
- Inside `QuickViewViewController` (`.item(.quickView)` scope): the header bar shows the
  filename, an `"Includes unsaved edits"` badge when dirty, a `Quick Look | Hex` toggle, an
  `Edit` button, and a `Pin` toggle (for following tabs); the body shows a full-size
  `QLPreviewView` (`.normal` style), `HexPreviewing` (`.regular` style), or a folder/error
  placeholder.
- **F4 / `⌃⌘E` from QuickView** (reusing `.browserEdit` bound in `.item(.quickView)` so
  `View › Edit` and the F-key bar's `F4 Edit` work seamlessly with no duplicate menu item)
  calls `onEdit(url, scope)` to open or focus the real `HexEditorItem`.
- `willClose()` explicitly closes `QLPreviewView`, clears `HexPreviewing`, and releases
  `SecurityScope`.

### D-f: F4 active-panel opening and browser action split

- Split `BrowserViewController`'s actions:
  - `browserView(_:)` (`F3`, `⌘Y`, `⌃⌘V`) and `browserViewInSamePanel(_:)` (`⇧F3`,
    `⇧⌃⌘V`): enabled for any selected entry (file, folder, or package; disabled on `".."`,
    empty selection, or `needsAccess`).
  - `browserEdit(_:)` (`F4`, `⌃⌘E`): enabled for regular files (and symlinks to regular
    files) only; disabled on folders, packages, and `".."` (D14).
  - `browserOpen(_:)` (Return, double-click, `⌘↓`): unchanged -- enters folders, opens
    files in the hex editor (§4.7).
- Update `AppDelegate.show(_:in:)` to insert new tabs into `controller.layout.activePanel`
  by default instead of always using `item.preferredSlot` (`.leftPanel`), so F4 in the
  right panel opens the hex editor tab in the right panel (D9, §4.8). Opening an
  already-open file still focuses its existing editor tab (D30).

## Commits

Each commit is one logical change of about 250 lines at most (hard limit 350). Order of
work: interface -> failing tests -> implementation.

### Part A: Core models and cross-kit protocols

   `getgrgid_r`, `listxattr` + `getxattr` size-only capped at 64 attributes), POSIX modes,
   BSD flags, formatted display values. Tests: regular files, folders, symlinks, xattrs,
   hard links, missing/unreadable paths.

## Out of scope

- Multiple `HexEditorItem` tabs editing one session (M11; M7 uses read-only
  `EditSnapshot` observers).
- QuickView state restoration across relaunch (transient derived state; only preview pane
  visibility and width restore).
- Recursive folder size or item counting in `FileMetadata` (kept O(1) for 100k-entry
  folders).
- Editing metadata, permissions, or xattrs; editing bytes inside QuickView or the preview
  pane.
- Text and Markdown editor modes for F4 (M9a–M9c; F4 opens hex mode until M9a).
- Hex search or Data Inspector inside QuickView (press F4 to open the full editor).
- Spacebar Quick Look shortcut (declined in `docs/reviews/Shortcuts.md` §3).
- User-editable key bindings and Preferences defaults (M10).
