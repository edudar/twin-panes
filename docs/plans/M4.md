# M4 plan: browser foundation

_Status: built 2026-11-23 (steps 0–14); PLAN.md D38–D43 and the §4.7 As built note are
the record. A performance pass is in progress (see "Performance pass" below). M3c is
still marked in progress (step 13, iCloud dataless files; the crash smoke test; step
14): the maintainer chose to start M4 with those left open._

## Context

M1b's browser (`BrowserItem`, `BrowserViewController`, `FileListTable`) lists one folder
at a time, synchronously, on the main actor:
- `DirectoryReader.entries(of:)` reads every entry's resource values, including
  `localizedTypeDescription`, and sorts them before the tab shows anything.
- Each visible row asks `NSWorkspace.icon(forFile:)` for its icon.
- Hidden files are always off, the order is always folders first and then name, and
  nothing updates until the tab lists the folder again.

PLAN.md §6, M4: async listing that never blocks the UI, back/forward history, sorting
by column, a hidden-files toggle, live updates (FSEvents), and a per-volume access flow
informed by the M0 spike. Three §9 items come due here:
- the path bar as a path control (deferred to M4)
- asking for access again when a saved bookmark no longer resolves
- open question 2, packages in the browser

**Done when:** a 100k-file folder can be listed, scrolled, sorted, filtered and updated
live with no main-thread stall over 50 ms, measured in the smoke test in the real app.

## Decisions (proposed)

### D-a: listing off the main actor, in batches, superseded by navigation

- **`FolderLister`** (TwinPanesCore) enumerates a folder on a background queue with
  `FileManager.enumerator(at:includingPropertiesForKeys:options:)`, prefetching only the
  cheap keys (`getattrlistbulk` underneath):
  - name
  - folder, package, symbolic link, hidden
  - size and date modified
- It delivers `Sendable` batches (about 2,000 entries, or whatever 50 ms has gathered)
  to the main actor, then a final "done" event, or an error (`.needsAccess`, `.notFound`,
  `.notAFolder`). The first batch arrives quickly, so the tab shows rows straight away.
- **Each listing has a generation.** Navigating, refreshing or closing the tab cancels
  the running listing, and any batch from an older generation is dropped before it
  reaches the model (the M3a review rule: late async results never mutate UI).
- **Symbolic links** are resolved in the same background pass, as `DirectoryReader`
  does today.
- `DirectoryReader` stays as a synchronous wrapper for tests and callers outside the
  browser.

### D-b: kind and icon on demand, cached by type

- The Kind column comes from `UTType(filenameExtension:)` (or `.folder`,
  `.symbolicLink`, `.package`), with its `localizedDescription` cached per type.
  `localizedTypeDescriptionKey` is the slow part of today's listing. It can differ from
  Finder's text for files with no extension or the wrong one, which is acceptable for a
  file list. The step 1 benchmark confirms the cost before we commit to this.
- **As built (step 1):** on 100,500 entries, reading Finder's type descriptions and
  display names took 7.5 s; the cheap keys take 0.73 s, and the kind for every entry
  0.3 s more. Names are now the real file names (`localizedName` hid extensions). The
  icon is per type; applications get theirs by path, from a 256-entry cache, on the main
  actor for now (visible rows only).
- Icons come from `NSWorkspace.icon(for: UTType)`, cached per type. Files with custom
  icons (and apps) get their own icon from a small LRU, loaded off-main for visible rows
  only.

### D-c: the folder model and sorting

- **`FolderListing`** (TwinPanesCore, a value type) holds:
  - the entries
  - a `SortOrder`: column (name, size, date, kind), ascending or descending, folders
    first (on by default, as in Finder)
  - whether hidden files show
  - the displayed rows, with the hidden ones filtered out
- Sorting more than about 5,000 rows runs off-main on a copy, with the generation check.
  Comparison keys (Finder's `localizedStandardCompare` order for names) are computed
  once per entry, not once per comparison.
- **As built (step 3):** `FolderListing` is a `Sendable` value with pure `merging`,
  `sorted(by:)` and `showingHidden`, and the order type is `ListingOrder` (Foundation
  has a `SortOrder`). There is no precomputed name key: Foundation offers none that
  matches `localizedStandardCompare`, which sorts 100k names in 0.64 s. So a batch is
  sorted on its own and merged in one linear pass (about 40 ms for 100k entries), and
  both run off-main above `mainActorLimit`.
- **Table headers** set the sort through `sortDescriptors`, with the standard indicator.
  The sort order belongs to the tab; it's restored with tabs in M5.
- **Selection survives a re-sort, a filter change and live updates,** by entry name.
  When the selected entry goes away, the selection moves to the row that took its
  place.

### D-d: back/forward history per tab

- Each `BrowserItem` keeps a back stack and a forward stack of `(folder, selected name)`.
  Every navigation pushes: entering a folder, going up, the path field, the path
  control, Go to Folder. A new navigation clears the forward stack.
- **Back** (⌘[) and **Forward** (⌘]), as in Finder, through the command registry.
- If a history folder no longer exists, it's skipped with a status message and the
  next entry is tried.
- A history entry the sandbox now refuses shows the access prompt, as any navigation
  does.

### D-e: hidden files

- ⇧⌘. toggles hidden files for the tab; the default stays off. A global default in
  Preferences is M10.
- Toggling filters the rows already loaded, so the folder isn't listed again (the
  listing always loads hidden entries).
- The status line counts what's shown and says how many are hidden, for example
  "1,204 items, 12 hidden".
- **As built (step 6):** the binding is `KeyChord(">", .command)`, because shifted
  symbols arrive as their shifted character, so the menu shows ⌘> rather than Finder's
  ⇧⌘., and other keyboard layouts get whatever ⇧. types there. User-editable bindings
  (M10) can fix it. The smoke test sends the event as AppKit delivers it.

### D-f: live updates with FSEvents

- **`FolderWatcher`** (TwinPanesCore) runs one `FSEventStream` per shown folder, with
  file-level events, about 0.2 s latency, and a dispatch queue.
  - It ignores events outside the folder itself; subfolders aren't recursed into.
  - It coalesces events into the set of changed names.
- **For each changed name**, the entry is read again (a stat via the same key set) and
  then inserted, updated or removed, keeping the sort.
- **A full re-list** (still async, then diffed by name) runs when FSEvents reports
  `MustScanSubDirs`, a dropped event, a root change, or more than 1,000 changed names
  in one batch.
- **The folder itself moving or being deleted:** the tab goes to the nearest folder up
  that still exists and says why in the status line.
- **The table updates through `insertRows` and `removeRows`** when the change is small,
  so the scroll position and selection stay put; a big change reloads the table.
- **As built (step 8):** `FolderWatcher` hands FSEvents a weakly held relay that is
  released on the stream's queue after it stops, and compares paths against `realpath`
  of the folder (`resolvingSymlinksInPath` turns /private/var into /var, so no event
  matched). Its tests wait at most 10 s per change and fail rather than hang.
- **The watcher stops** when the tab closes or leaves the folder. It holds the tab's
  `SecurityScope` for the folder's lifetime, as the listing does.

### D-g: per-volume access

- Going to a folder the sandbox refuses still shows the in-tab access prompt. M4 adds:
  - **On another volume:** the prompt offers "Grant Access to “<volume>”", with the
    open panel preset to the volume's root, so one grant covers the whole drive
    (`.volumeURLKey`).
  - **In the home folder:** the panel is preset to the home folder, so one grant covers
    it. TCC-gated folders (Desktop, Documents, Downloads, iCloud Drive) may still show
    the system prompt; the in-tab text says so.
- **A grant that stops resolving** (the volume was renamed, or the bookmark went stale
  and couldn't be refreshed) is no longer dropped silently. `FolderGrants` reports it,
  and the next navigation under that path shows the prompt with the panel preset to the
  old location. Recent files that no longer resolve go through the same flow. This is
  the §9 deferral.
- **A volume unmounting under a tab** comes in as a live-update root change (D-f): the
  tab goes to `/Volumes` or home and says the volume went away.
- A "Volumes" list in the sidebar is M5. M4 makes `/Volumes` itself browsable, as a
  folder.

### D-h: the path control

- A clickable path bar replaces the path field at the top of the tab. It's an
  `NSPathControl` (`.standard` style) with one component per folder. Clicking a
  component navigates there (pushing history).
- ⇧⌘G, or a click on the bar's empty area, swaps in today's editable path field with
  the full path selected. Return navigates, and Escape or losing focus swaps back.
- **Accessibility identifiers stay as they are** (`browserPath` for the field), so the
  smoke test drives both.

### D-i: packages (§9, open question 2)

- **Decision:** packages behave as in Finder. They list as files, so Return, F3 and F4
  open them as files: the editor refuses them (D14), and M7 previews them.
- **Show Package Contents** (⌥⌘↓, and in a context menu once there is one) enters the
  package as a folder. History and the path control treat it as an ordinary folder.

## Behaviour summary

| Action | Key | Result |
|---|---|---|
| Back / Forward | ⌘[ / ⌘] | previous / next folder in the tab's history, with its selection |
| Sort | click header | sorts by that column; clicking again reverses; folders stay first |
| Hidden files | ⇧⌘. | shows / hides dot-files and hidden-flag files in this tab |
| Go to Folder | ⇧⌘G | path bar becomes the editable field |
| Path component | click | goes to that folder |
| Show Package Contents | ⌥⌘↓ | enters a package as a folder |

While a listing runs, the status line says "Listing… 12,000 items" and the rows that
have arrived can already be scrolled and selected. Type-to-select works on what has
loaded.

## As built: what the 100k smoke test found (step 13)

The heartbeat (a 5 ms timer, worst gap per phase, Debug build) took the plan from 100–
770 ms stalls to under 50 ms. In the order they were found and fixed:
- **Test cost:** creating files with `FileManager.createFile` (atomic writes) took
  minutes; waiting on `entries.contains` walked 100k rows every 25 ms.
- **FSEvents storms:** creating 100k files overflows FSEvents, which then tells every
  stream it dropped events: re-lists now run one at a time, never during a listing,
  and a subfolder's rescan no longer re-lists its parent.
- **Row work on the main actor:** name diffs, selection lookups, a re-list's removals
  and freeing old listings moved into the off-main run (D39); batches grow so the
  main queue doesn't fill with them.
- **AppKit costs:** `reloadData` rebuilt every row view and its key-view loop (now
  only cells refresh); cells with Auto Layout, text fields and full-size icons cost
  100+ ms per screenful (now drawn); NSTableView's alternating stripes filled far
  more than the screen, 100–180 ms per navigation (found by sampling; now drawn by
  the row views); `FSEventStreamStart`, the path control's icons and starting
  security-scoped access cost up to 400 ms per navigation on a busy system.
- **Bugs it surfaced:** duplicate rows when a re-list raced the listing; an
  `NSTableViewException` (and duplicates) when a live update shared a run with the
  listing's last batches; the path bar widening the tab.

Mass deletion from outside (100k unlinks) is left as a known stall (PLAN.md §9).

## Performance pass (after step 14)

_Status: built 2026-11-23 (steps 1–5, 7, 8; step 6 dropped); not yet run on CI. PLAN.md
D44 and the §4.7 As built note are the record._

CI failed the 100k smoke test on macOS 15, 26 and 27. Worst main-thread gaps there:
listing 370–915 ms; sorting by kind 56–155 ms; scrolling 102–138 ms; 100 outside
changes 57–144 ms; the folder moved away 66–74 ms. The dev Mac stays under 50 ms. Not
every Mac is as fast as the dev Mac, so this is fixed in the app first. The CI limit is
discussed afterwards, with the numbers from these steps.

### What a Time Profiler pass found, worst first

1. **Drawing cells is most of the main thread's time.** `FileCell.draw` is about 70%
   of all drawing:
   - **Text, about 62% of that.** Every draw goes through
     `NSString.draw(with:options:attributes:)` with middle truncation, and builds a new
     font, paragraph style and attribute dictionary.
   - **Icons, about 32%.** `IconCache.small` only resizes a copy of the workspace icon,
     which keeps every representation up to 1024 px. Each draw picks one, scales it
     down and colour-matches it.
   CI runners have no GPU, so drawing costs several times more there.
2. **Listing batches rebuild every visible row.** Each batch adds more than 1,000 rows,
   so `refreshRows` falls back to `reloadData`, which throws away every row view and
   its key-view loop. Smaller refreshes use `reloadData(forRowIndexes:)`, which swaps in
   cells from the reuse queue, so they redraw even when their text is unchanged.
3. **The Kind sort and the Kind column share a lock.** `DirectoryEntry.kind` is looked
   up on every access in a global `Mutex<[UTType: String]>`, hashing the UTType each
   time. A Kind sort of 100k rows takes that lock about 3.4 million times off the main
   actor, while the main actor takes it for every Kind cell. CI's runners have 3 cores.
4. **Icons are looked up on the main actor.** The first lookup of a type, or of an
   app's path, goes through LaunchServices and IconServices: 83 ms for the package
   step's app icons on the dev Mac, and more on a cold CI machine. Each cell also checks
   `conforms(to: .application)` and hashes a UTType key.
5. **Size and date text are formatted per cell, per refresh**, with a new format each
   time.
6. **Four layers per row.** Each cell has its own layer and backing store, about 150
   bitmaps per screenful to commit.
7. **The smoke test can be fooled, and can't explain a failure.** It doesn't keep App
   Nap from throttling its heartbeat timer, and a failed gate doesn't say what stalled.

Off the main actor and fine: sorting by the other columns, merging batches and freeing
old listings. No stall over 15 ms happened while sorting on the dev Mac.

### Caches: what each one is keyed on, and what empties it

- **Icons:**
  - The key is the type identifier, the window's backing scale and its effective
    appearance. Folder icons follow the appearance and the accent colour.
  - The cache empties on `viewDidChangeEffectiveAppearance`,
    `viewDidChangeBackingProperties` and `NSColor.systemColorsDidChangeNotification`,
    and the visible rows redraw.
  - App icons are cached by path. An FSEvents change to that path drops its entry,
    for example after a custom icon is pasted in Get Info.
  - The type cache also empties when the app becomes active, since there's no
    notification for a newly installed app claiming a type. This costs a few dozen
    lookups, made off the main actor.
- **Cell text:**
  - Each cell keeps one prepared line, rebuilt when its text, width (a column or
    window resize) or selected state changes.
  - The line carries no colour. The current `labelColor` or `secondaryLabelColor` is
    applied when it's drawn, so dark mode and contrast changes need no rebuild.
  - The cached font and attributes have a version number. An appearance change, or a
    future font-size preference, bumps it, and every cell rebuilds its line on its
    next draw.
- **File names and attributes:**
  - A live update reads the entry again. The in-place refresh gives the cell the new
    name, size or date, and the text change rebuilds the line.
  - A test renames and resizes a visible file and checks the cell's new values.
- **Kind:**
  - Stored with each entry when the folder is read.
  - The UI language can't change while the app runs. A newly installed app's new
    description shows on the next listing, as in Finder.
- **Size and date text:** not precomputed for every entry. A locale, 12/24-hour or
  time-zone change would redo all of them, for rows nobody looks at. The formatters
  are made once and rebuilt on `NSLocale.currentLocaleDidChangeNotification` and
  `NSSystemTimeZoneDidChange`; the visible rows then refresh.

### Commits

Each commit is at most 250 lines, with a failing test first where one can fail. The
smoke test's worst gap per phase is recorded after each one.

1. **Smoke diagnostics.**
   - The smoke test holds a `ProcessInfo` activity, so App Nap doesn't throttle it.
   - The main actor's steps (show, refresh, icon lookup, cell drawing) are timed.
   - A failed gate prints its slowest steps.
2. **Kind stored with each entry.** The description is looked up once per type when
   the folder is read, so sorting and drawing take no lock.
3. **Icons drawn once**, in two commits:
   - **3a:** `IconCache` keeps one bitmap per type identifier, scale and appearance,
     emptied as described above.
   - **3b:** entries carry `isApplication`, and new types are looked up off the main
     actor before their rows are shown.
4. **Cheaper cell text.** Cached font and attributes with a version number, and each
   cell's truncated line, kept until its text, width or selection changes. The colour
   is applied when it's drawn.
5. **Refresh in place.**
   - The rows on screen are updated in their existing cells, so only cells whose text
     changed redraw.
   - Growth uses `noteNumberOfRowsChanged`. `reloadData` stays for big deletions.
   - The test renames and resizes a visible file.
6. ~~**Cached formatters**~~ **Dropped.** Measured (Debug build): a stored date style
   formats in 1.6 µs against 2.3 µs, and `ByteCountFormatter` takes about 8 µs whether
   stored or not, so a screenful of about 30 rows saves under 0.1 ms. Not worth the
   locale and time-zone invalidation it needs.
7. **One layer per row**: kept. Row views draw their cells into their own layer
   (`canDrawSubviewsIntoLayer`). Worst gap when the shown folder moves away: 22–47 ms
   before, 18–27 ms after. The smoke test checks that scrolling still draws the cells;
   `CALayer.render(in:)` doesn't capture drawn cells, so the look is checked by hand.
8. **Smoke and docs.** Built as planned. The appearance check switches the real
   window to dark and back and waits for the rows on screen to show that
   appearance's icons (`BrowserItem.shownIconsAreCurrent`); worst gaps 14–25 ms.
   Original wording:
   - The smoke test switches the real app between light and dark mode and checks a
     visible cell's text and icon change, with no gap over 50 ms.
   - The findings and results go into PLAN.md (§4.7 As built, §9) and this section.
