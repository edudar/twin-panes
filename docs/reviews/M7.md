### High (P1)

1. **Closed `EditorSession` stays reachable in `SessionRegistry` until deallocation**
   `[Resolved in 64a49fb]`
   - [SessionRegistry.swift](../../TwinPanesKit/Sources/TwinPanesCore/SessionRegistry.swift#L57-L66),
     [EditorSession+Folder.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession+Folder.swift#L90-L93),
     [ReadOnlyHexViewController.swift](../../TwinPanesKit/Sources/HexViewKit/ReadOnlyHexViewController.swift#L99)
   - `SessionRegistry.register(_:key:)` observes `session` only for `.saved`, never
     `.closed`. When `HexEditorItem.willClose()` calls `session.close()`,
     `HexEditorItem` is still retained by `MainFrameLayout`
     (`MainFrameViewController.swift` removes the item *after* `willClose()`) and by
     `closeItem`'s `Task`. During `session.notify(.closed)`,
     `QuickViewItem.sessionChanged(.closed)` calls `syncView()` ->
     `hexViewer.show(entry.url, scope:)` -> `sessions.session(for: url)` and receives
     the *already-closed* `EditorSession` back, permanently re-attaching to stale snapshot
     bytes instead of reloading from disk. `sessions.sessions` also keeps reporting
     closed sessions until deallocation.
   - **Fix:** Remove `session` from `entries` on `.closed` in
     `SessionRegistry.register(_:key:)`, add `public private(set) var isClosed = false` on
     `EditorSession` (guarded in `close()` for idempotency and filtered in
     `SessionRegistry.session(for:)` / `sessions`), and add a regression test calling
     `viewer.show(file, scope: nil)` after `session.close()` while `session` is still
     alive.

2. **100k-row `@MainActor` stall on multi-selection in the Preview Pane**
   `[Resolved in d434d4e (BrowserKit), c6f444f (App)]`
   - [AppDelegate+Preview.swift](../../TwinPanes/AppDelegate+Preview.swift#L49-L50),
     [AppDelegate+Preview.swift](../../TwinPanes/AppDelegate+Preview.swift#L100),
     [PreviewPaneViewController.swift](../../TwinPanesKit/Sources/BrowserKit/PreviewPaneViewController.swift#L120-L125)
   - `browserSelectionChanged` and `updatePreviewPane` call `browser.selectedEntries`
     (`ListingSelection.entries` -> `rows.map { listing.rows[$0] }`) synchronously on
     `@MainActor`, materializing up to 100k `DirectoryEntry` structs;
     `PreviewPaneViewController.show(entries:scope:)` then builds a second 100k filtered
     array (`entries.filter { $0.name != ".." }`), sums sizes synchronously, and frees
     both temporary arrays on `@MainActor`, defeating `Garbage(selection)` and violating
     [PLAN.md](../PLAN.md) §3 and D39.
   - **Fix:** Add `show(selection: ListingSelection, scope: SecurityScope?)` on
     `PreviewPaneViewController` (called from `AppDelegate+Preview.swift`): handle
     `count == 0` / `count == 1` in O(1), and for `count > 1` sum file sizes off
     `@MainActor` on `metadataQueue` after the debounce, guarded by `generation`.

3. **`QuickViewViewController` feeds dataless iCloud files directly to `QLPreviewView`**
   `[Resolved in 9f38832]`
   - [QuickViewItem.swift](../../TwinPanesKit/Sources/BrowserKit/QuickViewItem.swift#L209-L215),
     [QuickViewViewController.swift](../../TwinPanesKit/Sources/BrowserKit/QuickViewViewController.swift#L180-L188)
   - `QuickViewItem` checks `cloudDownloads.isDataless(url)` so `PreviewClassifier`
     chooses `.quickLook`, but `QuickViewViewController.syncView()` never checks
     `isDataless` (unlike
     [PreviewPaneViewController.swift](../../TwinPanesKit/Sources/BrowserKit/PreviewPaneViewController.swift#L216-L220))

     `QLPreviewView.previewItem`, risking an unintended iCloud download (violating D55 and

     `QuickViewViewController.syncView()` clear/hide `quickLookHost` and show an
     `"In iCloud — not downloaded"` placeholder when
     `activeMode == .quickLook && isDataless`.
