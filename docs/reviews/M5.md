Review of the M5 diff (`c2f9863..0ea630b`, 33 M5 commits including unified toolbar and `IconCache.forget` in `0ea630b`) against [M5.md](../plans/M5.md), [PLAN.md](../PLAN.md), and [AGENTS.md](../../AGENTS.md), surfacing **13 High (P1)**, **19 Medium (P2)**, and **11 Low (P3)** M5-introduced findings, plus **1 High** pre-existing finding hit on launch, test/smoke-test blind spots, and documentation drift.

**Status:** Pending fix waves (Commits 1–9 code/smoke, Commit 10 docs)

**Confirmed Decisions:**
1. **Include `0ea630b` (`Adopt unified AppKit header and full-height sidebar`):** Fold its `NSSplitViewController`, `MainToolbar`, and `IconCache.forget` review findings into this fix plan.
2. **Zoomed state + sidebar click:** Clicking a sidebar item while zoomed exits zoom (`layout.exitZoom()`) and opens the folder.

## 1. Findings by Severity

### High (P1)

1. **`AppDelegate.restoredEditor` can create duplicate `HexEditorItem` tabs on one `EditorSession`** (`[Pending — Commit 8]`)
   - [AppDelegate.swift](../../TwinPanes/AppDelegate.swift#L92-L101), [HexEditorItem.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorItem.swift#L108-L114)
   - Discards `isNew` from `sessions.open(...)` without checking `editorItem(showing: session) == nil`. While `isNew == false` is expected when claiming a recovered session from `LaunchRecovery`, it is also `false` if another restored tab or Finder open already created a tab for that file. Closing one duplicate calls `session.close()` and `session.stopWatching()`, destroying the crash-recovery folder for the surviving tab.
   - **Fix:** Check `guard editorItem(showing: session) == nil else { return nil }` before creating `HexEditorItem`.

2. **`MainWindowRestoration` centers and shows restored windows before AppKit applies saved frames** (`[Pending — Commit 8]`)
   - [MainWindowRestoration.swift](../../TwinPanes/MainWindowRestoration.swift#L19-L22), [AppDelegate.swift](../../TwinPanes/AppDelegate.swift#L259-L271)
   - `openMainWindow(restoring:)` centers/cascades at `900×600` and calls `controller.showWindow(nil)` *before* `completionHandler(window, nil)`. This flashes the window at the wrong size/screen, fires `viewDidAppear()` at `900 pt` (setting `hasPlacedDivider = true` and placing the divider before resizing), and triggers `invalidateRestorableState()` before AppKit applies the saved frame, Space, or miniaturized state.
   - **Fix:** Pass `show: Bool = true` to `openMainWindow(restoring:show:)` (`false` from `MainWindowRestoration`) so AppKit sizes and orders the window inside `completionHandler`.

3. **Clicking a secondary control (Find bar, Path field) in the inactive panel rips focus back to `preferredFirstResponder`** (`[Pending — Commit 7]`)
   - [MainFrameViewController.swift](../../TwinPanesKit/Sources/WorkspaceKit/UI/MainFrameViewController.swift#L157-L168), [MainFrameViewController.swift](../../TwinPanesKit/Sources/WorkspaceKit/UI/MainFrameViewController.swift#L286-L293)
   - `followFocus(to:)` calls `layout.activate(panel)` → `render()` → `focusCurrentItemIfChanged()`. Because `current?.id != lastFocusedItemID`, it unconditionally calls `window.makeFirstResponder(target ?? current.viewController.view)`, ripping focus out of the Find bar (causing typing to overwrite bytes in `HexView`) or closing the Path field.
   - **Fix:** Return early in `focusCurrentItemIfChanged()` when `window.firstResponder` is already an `NSView` descendant of `current.viewController.view`.

4. **Zoomed state allows hidden tab cycling (`⌃Tab`) and hidden sidebar clicks behind the zoom overlay** (`[Pending — Commits 7 & 8]`)
   - [MainFrameViewController.swift](../../TwinPanesKit/Sources/WorkspaceKit/UI/MainFrameViewController.swift#L140-L141), [AppDelegate.swift](../../TwinPanes/AppDelegate.swift#L282-L284), [AppDelegate.swift](../../TwinPanes/AppDelegate.swift#L329-L336)
   - `validateMenuItem` enables `selectNextTab`/`selectPreviousTab` while `layout.zoomedItem != nil`. Meanwhile the sidebar remains visible while zoomed: clicking a favorite/volume inserts a browser tab behind the zoom overlay without exiting zoom, and `onUpdate` highlights the hidden browser instead of `layout.zoomedItem`.
   - **Fix:** Disable `selectNextTab`/`selectPreviousTab` while zoomed; call `layout.exitZoom()` before opening a sidebar folder; compute sidebar highlight from `layout.zoomedItem ?? layout.focusedPanelItem`.

5. **Restoring editor scroll before window layout corrupts `.autoFit` scroll position and clamps near-EOF scrolls** (`[Pending — Commit 3]`)
   - [HexEditorItem+Restoring.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorItem+Restoring.swift#L56-L66), [HexView.swift](../../TwinPanesKit/Sources/HexViewKit/HexView.swift#L183-L223)
   - `restoreView(_:)` forces `_ = controller.view` (hardcoded `600×400` frame) and immediately calls `scroll(toTopRow: state.topRow)`. Under `.autoFit`, laying out at the real panel width lands at `0.5×–2×` the saved byte offset; under any mode, panels shorter than `400 pt` clamp `offset` too high near EOF and never restore it.
   - **Fix:** Add optional `topOffset: UInt64?` to `EditorState` and defer applying restored scroll until `HexEditorViewController.viewDidLayout()` once attached to a window with non-zero bounds.

6. **View-state edits (browser sort/hidden/selection; editor options/selection/scroll) never invalidate AppKit restorable state** (`[Pending — Commits 3 & 4]`)
   - [BrowserItem.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserItem.swift#L242-L256), [BrowserViewController.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserViewController.swift#L256-L260), [HexEditorViewController+Options.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController+Options.swift#L7-L29), [HexEditorViewController.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController.swift#L141-L149), [HexView.swift](../../TwinPanesKit/Sources/HexViewKit/HexView.swift#L275-L278)
   - Changing sort order, hidden files, browser selection, editor view options, cursor, or scroll without a subsequent navigation/tab change never calls `view.window?.invalidateRestorableState()`.
   - **Fix:** Call `view.window?.invalidateRestorableState()` on those view-state changes (without firing `onChange?()`).

7. **Restored background browser tabs silently lose their saved selection on re-save** (`[Pending — Commit 4]`)
   - [BrowserItem+Restoring.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserItem+Restoring.swift#L27-L35)
   - `restorableState` reads `controller.selectedName`, which is `nil` until `viewDidLoad()` runs `listFirstTime()` (also eagerly instantiating `lazy var controller`). Re-encoding before a background tab is shown overwrites `selected` with `nil`.
   - **Fix:** Encode `hasListed ? (controller.selectedName ?? controller.wantedSelection) : restoredSelection` without instantiating `controller` before `hasListed`.

8. **Main-thread stall opening the path completion list in a 100k-entry folder** (`[Pending — Commit 5]`)
   - [BrowserViewController+Completion.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserViewController+Completion.swift#L55-L63)
   - `control(_:textView:completions:...)` maps every element of `completion.matches` (up to `100,000` strings) on `@MainActor` and passes them all to `NSTextView.complete(nil)`, violating [PLAN.md](../PLAN.md) §3.
   - **Fix:** Cap offered popup items at `completion.matches.prefix(500)` while keeping prefix computation over all matches off-main.

9. **Stale/cancelled path-completion tasks mutate field editor after Escape or double-Tab; `CompletionNames` blocks cooperative pool & duplicates in-flight reads** (`[Pending — Commits 1 & 5]`)
   - [BrowserViewController+Completion.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserViewController+Completion.swift#L11-L28), [BrowserViewController+PathBar.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserViewController+PathBar.swift#L85-L92), [CompletionNames.swift](../../TwinPanesKit/Sources/TwinPanesCore/CompletionNames.swift#L46-L55)
   - `completePath` doesn't cancel prior `pendingCompletion` and never checks `!Task.isCancelled`, `isEditingPath`, or `pathField.currentEditor() === textView` after `await` (AppKit's shared field editor retains old text after Escape).
   - `CompletionNames.names(in:)` runs blocking directory enumeration on `Task.detached` (cooperative pool, violating [PLAN.md](../PLAN.md) §3) and launches duplicate full 100k-entry scans on concurrent calls for the same uncached folder.
   - **Fix:** Cancel `pendingCompletion` at the top of `completePath(in:)` and in `BrowserViewController.deinit`, guarding cancellation and active editor identity after `await`. In `CompletionNames`, dispatch reads onto a private serial `DispatchQueue` with `withExtendedLifetime(scope)` and coalesce concurrent in-flight reads per folder.

10. **`PathCompletion.sharedLength` truncates typed text on Unicode context-sensitive case folding and allocates O(matches × nameLength) heap strings** (`[Pending — Commit 1]`)
    - [PathCompletion.swift](../../TwinPanesKit/Sources/TwinPanesCore/PathCompletion.swift#L48-L58), [PathCompletion.swift](../../TwinPanesKit/Sources/TwinPanesCore/PathCompletion.swift#L72-L78)
    - Matching uses whole-string `.lowercased()` while `sharedLength` lowercases each `Character` individually (`String($0).lowercased()`). For Greek final sigma (`"ΟΣ"` vs `"ος"`), both match `"/x/ος"`, yet `sharedLength` returns `1` and deletes the typed `ς`.
    - `names.map { $0.map { String($0).lowercased() } }` allocates millions of single-character `String`s (`~35–100+ MB` churn) on 100k matches even when the first two names differ at index 0.
    - **Fix:** Use consistent case-insensitive comparison and stream the shared prefix iteratively in O(single name length) memory, stopping once `commonLength == 0`.

11. **`VolumeWatcher` leaks 3 `NotificationCenter` block observers without `stop()` + deadlock race in `VolumeWatcherTests`** (`[Pending — Commit 4]`)
    - [VolumeWatcher.swift](../../TwinPanesKit/Sources/BrowserKit/VolumeWatcher.swift#L12), [VolumeWatcher.swift](../../TwinPanesKit/Sources/BrowserKit/VolumeWatcher.swift#L30-L48), [VolumeWatcherTests.swift](../../TwinPanesKit/Tests/BrowserKitTests/VolumeWatcherTests.swift#L71-L98)
    - `VolumeWatcher` has no `deinit` removing its block observers.
    - `VolumeWatcherTests.aReadThatFinishesAfterANewerOneIsDropped` posts `didMountNotification` before ensuring ticket 1 entered `read()`, which can deadlock permanently if ticket 2 acquires the lock first.
    - **Fix:** Remove observers in `VolumeWatcher.deinit` and add a `firstStarted` barrier + `.timeLimit(.minutes(1))` in `VolumeWatcherTests`.

12. **`toggleSidebarShown(_:)` and `0ea630b` `NSSplitViewController` drop sidebar width & drag-resize tracking** (`[Pending — Commit 7]`)
    - [MainFrameViewController.swift](../../TwinPanesKit/Sources/WorkspaceKit/UI/MainFrameViewController.swift#L20-L36), [MainFrameViewController.swift](../../TwinPanesKit/Sources/WorkspaceKit/UI/MainFrameViewController.swift#L102-L105), [MainFrameViewController.swift](../../TwinPanesKit/Sources/WorkspaceKit/UI/MainFrameViewController.swift#L275-L281)
    - `toggleSidebarShown(_:)` captures `frame.width` unconditionally before layout (`0.0` in `MainFrameSidebarTests.aHiddenSidebarIsSavedAndRestoredHidden`).
    - In `0ea630b`, `splitViewController` owns `splitView.delegate`, so drag-resizing or drag-collapsing the sidebar no longer updates `sidebarWidth` or calls `invalidateRestorableState()`, `toggleSidebar:` hits `splitViewController` directly (even when `sidebar == nil`), and collapsing a focused sidebar leaves focus outside the active panel.
    - **Fix:** Capture `sidebarWidth` only when `hasPlacedDivider && width >= 120`, subclass `NSSplitViewController` privately to forward resize notifications and `toggleSidebar:` to `MainFrameViewController`, and refocus the active panel when collapsing a focused sidebar.

13. **`IconCache.forget` in `0ea630b` mixes Unicode-canonical `String.hasPrefix` with raw UTF-8 byte offsets** (`[Pending — Commit 4]`)
    - [FileListTable.swift](../../TwinPanesKit/Sources/BrowserKit/FileListTable.swift#L234-L245)
    - When `parent` and cached `path` differ in NFC vs NFD (e.g., `café`), `hasPrefix` is `true` while `parent.utf8.count` slices mid-filename (missing eviction or evicting the wrong sibling); filenames starting with a combining mark break `hasPrefix` across `/`.
    - **Fix:** Match and slice in the same code-unit space (`NSString.hasPrefix` + `NSString.length`/`substring(from:)`) and short-circuit `guard !names.isEmpty`.

14. *(Merged P1 for Smoke/Child isolation — see #13 in Fix Plan Commit 9)* **`--smoke-child` leaks temp folders/`UserDefaults`, races child teardown, and leaves orphan `crash-edit` on parent timeout** (`[Pending — Commit 9]`)
    - [SmokeChild.swift](../../TwinPanes/SmokeChild.swift#L80-L92), [SmokeTest+Relaunch.swift](../../TwinPanes/SmokeTest+Relaunch.swift#L42-L82), [AppDelegate.swift](../../TwinPanes/AppDelegate.swift#L24-L51)
    - `--smoke-child` leaks `smoke-recents-*` on every run and `smoke-grants-*` on `SIGKILL` (`crash-edit`) and error exits; `launchChild` terminates immediately upon seeing `<step>.json` without waiting or escalating to `SIGKILL`; `crash-edit` has no self-timeout; `--smoke-test`/`--bench` still use real `SessionFolder.defaultRoot` (pre-existing, exacerbated in M5).
    - **Fix:** Place `SmokeChild` grants/recents/sessions inside `child.folder`, isolate `sessionsRoot` for all `isIsolatedRun`s, write `<step>.json` after cleanup before exit, wait/escalate/`waitUntilExit()` cleanly, and add a `30 s` self-timeout on `waitsToBeKilled`.

*(Pre-existing P1 hit on M5 launch)* **15. `EditorSession.init(recovering:)` resolves manifest bookmarks without `.withoutMounting`** (`[Pending — Commit 2]`)
    - [EditorSession.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession.swift#L125)
    - Called synchronously in `applicationWillFinishLaunching` (`AppDelegate.swift#L132`); can stall launch trying to mount an unmounted/network volume. Fix: add `.withoutMounting`.
