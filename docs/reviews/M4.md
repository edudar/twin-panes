# M4 Code, Architecture, Tests & Documentation Review

Review of the full M4 diff (`a4dfc59..475afb3`, 44 files, +4,930 / −129 lines) against [M4.md](../plans/M4.md) and [PLAN.md](../PLAN.md), surfacing **1 Critical**, **12 High**, **13 Medium**, and **6 Low** findings, plus test/smoke-test blind spots and documentation drift.

**Status:** Resolved (`2ad574f`..`02aed24`)

**Resolved Decisions:**
1. **Blocking main-thread IPC in `--smoke-test`:** Keep `GapMeter` CPU-only as the tight gate (`50 ms × factor`).
2. **`DirectoryReaderPerformanceTests`:** Replace the no-baseline XCTest `measure` block rather than keeping an unasserted performance test.
3. **Custom icons for non-app files (D-b):** Check custom icons lazily (`com.apple.FinderInfo`) off the main thread without degrading 100k-row performance.

## 1. Findings by Severity

### Critical

1. **`FolderListing.rowChanges` corrupts the visible table & selection when a live update changes an entry's sort rank** (`[Resolved in 2ad574f]`)
   - [FolderListing.swift](../../TwinPanesKit/Sources/TwinPanesCore/FolderListing.swift#L156-L169), [BrowserViewController.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserViewController.swift#L192-L219), [BrowserItem.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserItem.swift#L272-L278)
   - When sorted by **Size**, **Date Modified**, or **Kind** (or when a symlink flips between folder and file) and an existing file changes rank (`before[name] != after[name]`), `rowChanges` returns `removed: []`, `inserted: []`, `changed: [afterRow]`. `applyRowChanges` reloads only `afterRow`, leaving intermediate rows stale/duplicated on screen and desyncing selection from `rows`.
   - Missed by [FolderListingTests.swift](../../TwinPanesKit/Tests/TwinPanesCoreTests/FolderListingTests.swift#L143) (re-merges unmodified `all[20]`) and [BrowserLiveUpdateTests.swift](../../TwinPanesKit/Tests/BrowserKitTests/BrowserLiveUpdateTests.swift#L71) (resizes under `.name` sort only).

### High

2. **Delete resurrection, stale-read overwrite & uncancelled relist in live-update pipeline** (`[Resolved in 831e3a7; deduplication in 2ad574f]`)
   - [BrowserItem+Live.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserItem+Live.swift#L47-L136), [BrowserItem.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserItem.swift#L152-L199), [FolderListing.swift](../../TwinPanesKit/Sources/TwinPanesCore/FolderListing.swift#L89-L111)
   - **Delete resurrection:** While `isMerging == true`, if read #1 buffers `foo` in `pendingBatch` and read #2 deletes `foo` (`apply(removing: ["foo"], adding: [])`), `pendingBatch` is not purged of `foo` — `merging` resurrects the deleted file. Similarly, `pendingReplacement` from `relist()` does not clear older `pendingBatch`/`pendingRemovals`.
   - **Out-of-order `read(_:)`:** Overlapping FSEvents batches spawn unstructured `Task.detached` tasks with no sequence/order guard; a slower older read can finish after a newer one and overwrite newer metadata or resurrect a deleted file.
   - **Uncancelled `relist()` & missing `deinit`:** `relist()` does not store its `FolderLister`, so `stopListing()` / `willClose()` cannot cancel an in-flight 100k-file relist. `BrowserItem` also lacks `deinit` to stop `lister`/`watcher`, and neither `startListing()`, `relist()`, nor `read(_:)` retains `self.scope` across background I/O (violating [PLAN.md](../PLAN.md) §5).
   - **Duplicate entries:** `FolderListing.merging(_:)` never deduplicates by name (which POSIX `readdir`/`getattrlistbulk` can emit across concurrent modifications), breaking `rows(named:)` and `rowChanges`.

3. **`BrowserItem.granted(_:)` navigates away from a denied subfolder when granting a covering parent** (`[Resolved in 264e372]`)
   - [BrowserItem.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserItem.swift#L382-L385), [AccessRequest.swift](../../TwinPanesKit/Sources/BrowserKit/AccessRequest.swift#L12-L36), [BrowserViewController.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserViewController.swift#L324-L336)
   - When `AccessRequest` asks to grant Home (`~`), a volume (`/Volumes/Drive`), or a lost parent grant "to show `Subfolder`", `granted(url)` calls `go(to: url == folder ? nil : url)`. Because `url != folder`, it navigates away to `~` or `/Volumes/Drive` (pushing `Subfolder` onto `backStack`) instead of staying in and re-listing `Subfolder`. Raw `URL` equality is also trailing-slash sensitive, and a missing `lost` directory is passed straight to `NSOpenPanel.directoryURL`.

4. **Pressing Return on the Access Prompt navigates to the parent folder instead of clicking "Grant Access…"** (`[Resolved in 264e372]`)

   - `grantButton.keyEquivalent = "\r"`, yet the hidden `tableView` remains `firstResponder` with row 0 (`".."`) selected (`numberOfRows` still returns 1). `CommandDispatcher` intercepts Return in `.item(.browser, part: "fileList")` and triggers `browserOpen` → `goToParent()`.

6. **`listed()` continuation leak/hang on `willClose()` & premature resume on queued small-folder relist** (`[Resolved in 1a916a2]`)
   - [BrowserItem.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserItem.swift#L88), [BrowserItem.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserItem.swift#L180-L199), [BrowserItem+Live.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserItem+Live.swift#L103-L109)
