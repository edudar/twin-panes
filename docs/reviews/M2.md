# M0–M2 Code, Architecture & Test Review

Audit of the M0, M1, M1b, and M2 implementation and test suite against [PLAN.md](../PLAN.md).

**Status:** Resolved (`4f70659`..`b9588bc`)

**Confirmed Decisions:**
- Core Text pre-shaped glyphs and horizontal scrolling in `HexView` are included in M2.
- `browser.switchPanel` is removed/deferred to M5.
- Heavy 256 MiB / 4 GiB throughput checks are split out of `--smoke-test` into `--bench`.
- `⌘G` is the primary menu shortcut over `F3` for Find Next.
- Dropped folders open a browser tab and record a `FolderGrants` bookmark.

## 1. Implementation Gaps & Bugs

### High-impact bugs (broken or crashing behavior)

- **Drag-and-drop onto the main window is dead at runtime** (`[Resolved in 126cf7b]`) — [MainWindow.swift](../../TwinPanesKit/Sources/WorkspaceKit/UI/MainWindow.swift#L6-L45)
  `NSWindow` does not conform to `NSDraggingDestination`, and `MainWindow` neither conforms to `NSDraggingDestination` nor marks `draggingEntered(_:)` / `performDragOperation(_:)` as `@objc`. Inspecting the generated `WorkspaceKit-Swift.h` confirms neither selector is exposed to Objective-C, so AppKit never calls them. Drag-and-drop to open files is an M1 requirement (§6).

- **`ByteSource.prefetch` traps on empty ranges** (`[Resolved in b7117d8]`) — [ByteSource.swift](../../TwinPanesKit/Sources/TwinPanesCore/ByteSource.swift#L135-L164), [ByteSource.swift](../../TwinPanesKit/Sources/TwinPanesCore/ByteSource.swift#L224-L226)
  Unlike `cachedBytes` and `read`, `prefetch` does not guard `if range.isEmpty`. Calling `Self.pages(covering: range)` on `0..<0` (empty file) underflows `range.upperBound - 1`, and on a clamped post-EOF range at a page boundary (e.g. `65536..<65536`) constructs an invalid `ClosedRange` (`1...0`). Current callers mask this by guarding before calling `prefetch`, but the public API traps.

- **`HexView` and `InspectorView` cancel each other's prefetches** (`[Resolved in b7117d8, 6cae3e7]`) — [ByteSource.swift](../../TwinPanesKit/Sources/TwinPanesCore/ByteSource.swift#L65), [HexEditorViewController.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController.swift#L124-L133), [HexView+Drawing.swift](../../TwinPanesKit/Sources/HexViewKit/HexView+Drawing.swift#L133-L155)
  `ByteSource` has a single `latestPrefetch` counter. When jumping (`go(to:)`) or moving the cursor to an uncached page with the inspector open, `updateInspector()` calls `item.prefetch(cursor..<cursor+8)` and then `HexView.draw` immediately calls `item.prefetch(visible ± screen)`, cancelling the inspector's prefetch. The inspector callback receives `nil` error while bytes are still uncached and renders `—` for every row; when `HexView`'s prefetch finishes, it redraws `HexView` without re-updating the inspector. Conversely, moving the cursor onto an uncached byte cancels an in-flight viewport prefetch.

- **`HexView.requestPrefetch` ignores downward scroll changes while a prefetch is pending** (`[Resolved in da17b07]`) — [HexView+Drawing.swift](../../TwinPanesKit/Sources/HexViewKit/HexView+Drawing.swift#L139-L141)
  `pendingPrefetch.map({ !$0.contains(range.lowerBound) }) ?? true` skips issuing a newer prefetch whenever the *start* of the new margin-expanded range still overlaps `pendingPrefetch`, even when the newly visible rows at the bottom are outside `pendingPrefetch`. This defeats prefetch superseding during incremental downward scrolling on slow volumes. It should check whether `pendingPrefetch` covers the *visible* range (`first..<end`).

### Plan gaps (M0–M2 requirements not yet met or diverged)

- **`HexView` drawing does not use Core Text or pre-shaped glyphs (§4.4)** (`[Resolved in da17b07]`) — [HexView+Drawing.swift](../../TwinPanesKit/Sources/HexViewKit/HexView+Drawing.swift#L91-L130)
  `drawRow` allocates `[Character]` buffers, converts to `String`/`NSString`, rebuilds 3 attribute dictionaries *per row*, and calls `NSString.draw(at:withAttributes:)` 3 times per row per frame (~180+ shaping/drawing calls on a tall 120 Hz display).

- **No horizontal scrolling in `HexView`** (`[Resolved in e551819]`) — [HexView.swift](../../TwinPanesKit/Sources/HexViewKit/HexView.swift#L61-L134)
  Selecting 32 bytes/row (~142 cells) or `offsetBase = .both` in the default 900 pt window (especially with the 280 pt inspector open) clips the hex/text columns off the right edge with no horizontal scroll path.

- **Copy selection blocks `@MainActor` and evicts the entire LRU cache** (`[Resolved in da17b07, 6cae3e7]`) — [HexView+Input.swift](../../TwinPanesKit/Sources/HexViewKit/HexView+Input.swift#L151-L165), [HexSelection.swift](../../TwinPanesKit/Sources/HexViewKit/HexSelection.swift#L56)
  `copySelection` calls `dataSource.read(range)` synchronously on the main thread for up to `HexCopy.maxBytes` (16 MiB — equal to the entire 256 × 64 KiB page cache), stalling the UI and evicting every cached viewport page. Using `readSequential` (and async I/O for larger ranges) avoids both.

- **`SecurityScope` lifetime and partial-file cleanup in `saveSelection` (§5)** (`[Resolved in 6cae3e7]`) — [HexEditorViewController.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController.swift#L192-L216), [ByteReading+Write.swift](../../TwinPanesKit/Sources/TwinPanesCore/ByteReading+Write.swift#L4-L23)
  `Task.detached` captures `item.source` but not `item`'s `SecurityScope`, violating §5 ("Closing the tab that started a copy doesn't revoke the copy's access"). Also, `ByteReading.write` explicitly leaves partial files on failure for the caller to handle, but `saveSelection` never removes the partial file if writing throws.

- **Command/menu system gaps vs §4.11:**
  - **Dangling command `browser.switchPanel`** (`[Resolved in 217ad75 — deferred to M5]`): registered in [Commands.swift](../../TwinPanes/Commands.swift#L99), bound to `Tab` in `fileList` ([Commands.swift](../../TwinPanes/Commands.swift#L149)), and added to the View menu ([MainMenu.swift](../../TwinPanes/MainMenu.swift#L84)), but no responder implements `browserSwitchPanel(_:)`. It stays permanently grayed out in the View menu.
  - **Menu key equivalents are not refreshed on focus change** (`[Resolved in 126cf7b]`): [MenuBindingUpdater.swift](../../TwinPanesKit/Sources/WorkspaceKit/Commands/MenuBindingUpdater.swift#L41-L53) only runs in `menuNeedsUpdate(_:)`, never on focus/responder changes as §4.11 specifies.
  - **Double dispatch attempt on unhandled key equivalents** (`[Resolved in 126cf7b]`): [MainWindow.swift](../../TwinPanesKit/Sources/WorkspaceKit/UI/MainWindow.swift#L9-L19) calls `dispatcher.handle` in both `sendEvent` and `performKeyEquivalent`; unhandled modifier keys run `dispatcher.handle` twice.
  - **Arbitrary menu shortcut tie-breaking** (`[Resolved in 99e7623, 217ad75]`): [CommandRegistry.swift](../../TwinPanesKit/Sources/WorkspaceKit/Commands/CommandRegistry.swift#L54-L55) picks a command's displayed menu shortcut by sorting `chord.description` alphabetically, so `Edit › Find › Find Next` shows `F3` instead of `⌘G` (because `"F3" < "⌘G"`).

- **Incomplete M0/M1/M2 verification & docs** (`[Resolved in 0c8e87f, b6eb5d6]`):
  - [SANDBOX-SPIKE.md](../SANDBOX-SPIKE.md#L115) notes an unrun M0 case ("a file grant alone outside Documents"), and `SandboxProbe` checks mode/xattrs/tags/creation date but not ACLs (§4.3, §5).
  - No Instruments pass or throttled/slow-volume scroll measurement (§7) is recorded yet.
  - [README.md](../../README.md#L43-L44) still lists M2 ("Search and inspect") under "Where it's going".

### Smaller edge-case bugs

- **Find bar UX** (`[Resolved in 6cae3e7]`) — [HexEditorViewController+Find.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController+Find.swift):
  - `find(_:)` ([L66](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController+Find.swift#L66)) guards `!findBar.isHidden`, so closing the find bar and pressing `⌘G` reopens the bar instead of finding next.
  - `findAll()` ([L90-L91](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController+Find.swift#L90-L91)) does not unhide `findBar`, so invoking Find All from the menu while the bar is hidden leaves progress and match count invisible.
  - `HexView.select(_:)` ([HexView.swift](../../TwinPanesKit/Sources/HexViewKit/HexView.swift#L178-L186)) checks `!position.visibleRows.contains(row)` and passes `reveal: false`, so a match on a *partially* visible top/bottom row isn't scrolled fully into view.
- **Browser path input & symlink handling:**
  - `BrowserViewController.pathEntered` (`[Resolved in 27d13d9]`, [BrowserViewController.swift](../../TwinPanesKit/Sources/BrowserKit/BrowserViewController.swift#L118-L128)): empty input navigates to `/` (process CWD) instead of reverting, and `hasPrefix("~")` mangles `~otheruser` into `/Users/<me>otheruser` (should match `"~"` or `"~/"`).
  - `DirectoryReader.entry` (`[Resolved in 75b3dba]`, [DirectoryReader.swift](../../TwinPanesKit/Sources/TwinPanesCore/DirectoryReader.swift#L66-L72)): for a symlink pointing to a package (e.g. `.app`), `isDirectory` is read from the resolved target (`true`) while `isPackage` is read from the symlink (`false`), listing it as a browsable folder instead of a package; symlinks to files also report the symlink's size instead of the target's.
- **Bookmark store accumulates dead entries & re-resolves on every lookup** (`[Resolved in 75b3dba]`):
  - [BookmarkStore.swift](../../TwinPanesKit/Sources/TwinPanesCore/BookmarkStore.swift#L24) filters with `Self.path(of: $0) != path`. Unresolvable bookmarks have `path == nil`, so `nil != path` keeps them in `UserDefaults` indefinitely (unbounded in `FolderGrants`, consuming slots in `RecentFiles`). Every `FolderGrants.scope(covering:)` call ([FolderGrants.swift](../../TwinPanesKit/Sources/TwinPanesCore/FolderGrants.swift#L24)) resolves every stored bookmark synchronously on `@MainActor`.
- **`MainFrameViewController.closeItem` double-close race & `MainFrameLayout.move` triple-notify** (`[Resolved in 99e7623]`):
  - [MainFrameViewController.swift](../../TwinPanesKit/Sources/WorkspaceKit/UI/MainFrameViewController.swift#L132-L141): two rapid close calls on the same tab both pass `layout.item(id)` before the `Task` runs and can invoke `item.willClose()` twice (needs a re-check of `layout.item(id) != nil` after `await`).
  - [MainFrameLayout.swift](../../TwinPanesKit/Sources/WorkspaceKit/MainFrameLayout.swift#L84-L91): `move` calls `remove` (notifies), `insert` (notifies), then `notify()` again — firing 3 renders and transient un-zooming/focus loss.

## 2. Insufficient Tests

- **`WorkspaceKit` UI & command-dispatch layer is largely untested in unit tests** (`[Resolved in 99e7623, 126cf7b]`, `WorkspaceKitTests`):
  - **No tests at all** for `MainWindow` (which let the broken drag-and-drop slip through), `CommandDispatcher` (responder-chain targeting, `NSMenuItemValidation` / `NSUserInterfaceValidations`, falling through from a disabled candidate to the next scope's candidate, sheet suppression), `FocusChain` (field editor delegation, `window` firstResponder fallback), `MenuBindingUpdater`, or `MainWindowController.windowShouldClose` (dirty prompt approve/cancel).
  - `CloseCoordinatorTests` never tests the `inProgress` re-entrancy guard or the case where a session becomes clean while an earlier prompt is up ([CloseCoordinator.swift](../../TwinPanesKit/Sources/WorkspaceKit/CloseCoordinator.swift#L65-L71)).

- **`TwinPanesCore` edge cases** (`[Resolved in b7117d8, 75b3dba, 0c8e87f]`):
  - `ByteSourceTests`: missing 0-byte file tests (especially `prefetch(0..<0)`), non-regular types beyond directories (broken symlink, symlink to regular file, FIFO), `EACCES` unreadable file, multi-page truncation (full page 0 + truncated page 1), and actual `ByteSource` cache eviction + reload (only `PageCache` is tested directly).
  - `SecurityScope`: zero unit tests.
  - `BookmarkStoreTests` & `FolderGrants`: missing stale-bookmark refresh behavior, `refresh` of a missing entry, dead-entry retention, and path-prefix boundary safety (`/tmp/foo` must not cover `/tmp/foobar`).
  - `DirectoryReaderTests`: missing broken symlinks, symlinks to files, symlinks to packages, empty directory, and `needsAccess` error mapping.
  - `InspectorTests`: missing negative 32-bit Unix timestamps (pre-1970), `NaN`/`Infinity` floats and Mac absolute times, `Windows FILETIME` out-of-range (`UInt64.max`), and truncated multi-byte UTF-8/UTF-16 at EOF.
  - `SearchPatternTests` / `SearcherTests`: missing UTF-16 surrogate pairs (e.g. emoji), `SearchPattern.text` exceeding `maxLength`, `Searcher` on empty files / `offset > length` / `pattern.count > length`, `Searcher.all(..., limit: 0)`, error propagation when `readSequential` throws mid-scan, and progress totals on wrapped two-pass `next`.

- **`HexViewKit` interactions and edge cases** (`[Resolved in 46ffaa9]`):
  - `HexViewBehaviourTests`: no tests for `copy(_:)` / `copySelection(as:)` / `selectionTooLargeToCopy` delegate trigger, `Shift`-extending keyboard navigation, `Tab` switching `activeColumn`, `Select All`, `mouseDown` / `mouseDragged` (including Shift-click and text-column click), `scrollWheel` / `scrollerMoved`, rendering with `highlights` populated, empty-file drawing, or incremental scrolling while a prefetch is pending.
  - `HexLayoutTests`: missing `offsetBase: .decimal`, `grouping: 2` and `grouping: 8` (verifying no extra 8-byte gap at `grouping == 8`), `.fixed(8)` / `.fixed(32)`, and `hit(cell:)` boundary cells (`hexStart - 1`, `textStart - 1`, inter-column gaps).
  - `HexOffsetParserTests`: missing comma separators (`1,000`), negative hex (`-0x10`), non-clamping subtraction (`-10` from `100`), bare `"0x"` / `"+"` / `"-"`, and `UInt64` overflow on absolute values.

- **`EditorKit` controller & inspector integration** (`[Resolved in 6cae3e7, 35c6c61]`):
  - Zero unit tests in `EditorKitTests` for `InspectorView` integration (`toggleInspector`, `updateInspector` on cached vs uncached bytes — which would have caught the competing-prefetch bug), `FindBarView` option/encoding switching and invalid-pattern status, `editorUseSelectionForFind` (including the 4096-byte cap), `editorCloseFind` cancelling vs closing, `findAll` truncated results falling back to rescanning on `find(.forward)`, and `HexEditorViewController+Options` (`setBytesPerRow`/`setGrouping`/`setOffsetBase`/`setTextEncoding` + menu checkmarks).

- **`BrowserKit` controller behavior** (`[Resolved in 27d13d9]`):
  - `BrowserItemTests` never tests `BrowserViewController` (`pathEntered` tilde/empty/invalid handling, `validateMenuItem` enablement, `granted(_:)` updating grants and re-listing).

- **Missing §7 performance & slow-volume test harness** (`[Resolved in 35c6c61, 217ad75]`):
  - `PLAN.md §7` calls for XCTest `measure` performance tests including a **throttled/slow-volume read source** to verify scroll frame time with placeholders. None exist yet; `SmokeTest` only measures cached redraws after a 5 ms settle on local disk and prints numbers without thresholds.

## 3. Tests That Add Bloat Without Much Value

Overall the unit tests are fairly lean (`MainFrameLayoutTests`, `FindStepperTests`, `HexModelTests`, and `HexOffsetParserTests` are concise and high-signal). The main sources of bloat, redundancy, or flakiness are:

- **[HexEditorSearchTests.swift](../../TwinPanesKit/Tests/EditorKitTests/HexEditorSearchTests.swift#L13-L52) — 4 GiB sparse files + `Task.sleep(300ms)` to test a generation counter** (`[Resolved in a09faa3, ae596dd]`)
  Both tests create 4 GiB sparse files on disk solely to make a search slow, and `aReplacedSearchCannotOverwriteTheNewerResult` polls up to 5 s then sleeps an arbitrary 300 ms (which isn't even guaranteed to outlast a 4 GiB scan under Thread Sanitizer). Also, `closingStopsARunningSearch` doesn't await the background `Searcher` worker's exit, leaving a slot on the 2-worker global `Searcher.pool` occupied while parallel tests run. Injecting a gated/fake `ByteReading` would make these tests deterministic and sub-millisecond.

- **[SmokeTest.swift](../../TwinPanes/SmokeTest.swift) (540 lines) — heavy disk churn & duplicated unit tests inside a 30 s CI gate** (`[Resolved in 217ad75]`)
  - `realDataSearch` ([L408-L446](../../TwinPanes/SmokeTest.swift#L408-L446)) writes **256 MiB** of random bytes to disk and scans them on *every* push/PR across all 3 macOS runners just to print MiB/s with no assertion — contradicting `PLAN.md §7` ("Tagged slow, run nightly; mind runner disk space") and eating into the hardcoded 30 s timeout ([L20](../../TwinPanes/SmokeTest.swift#L20)). `scrollThroughFile` ([L385-L396](../../TwinPanes/SmokeTest.swift#L385-L396)) also runs 480 redraws + 2.4 s of sleeps just to print timings.
  - Substantial parts of `SmokeTest` duplicate pure logic already covered by `swift test` (`CommandRegistry` resolution, `CloseCoordinator.dirtySessions`, `DirectoryReader` ordering, `HexView.go`/`statusText`/`copySelection`). Trimming `SmokeTest` to sandbox/AppKit-only checks and moving the 256 MiB / 4 GiB throughput checks to a separate benchmark/nightly job would remove both bloat and timeout risk.

- **[HexViewBehaviourTests.swift](../../TwinPanesKit/Tests/HexViewKitTests/HexViewBehaviourTests.swift#L72-L74), [L97-L103](../../TwinPanesKit/Tests/HexViewKitTests/HexViewBehaviourTests.swift#L97-L103)** (`[Resolved in 46ffaa9]`):
  - `clipsToItsBounds` asserts a single stored boolean set in `init`.
  - `drawsShortDataAsPlaceholders` has **no assertions at all** (it only checks that `render()` doesn't trap; it doesn't assert prefetching or error handling).

- **[SearchPatternTests.swift](../../TwinPanesKit/Tests/TwinPanesCoreTests/SearchPatternTests.swift#L44-L56) (`anchorsOnTheRarestExactByte`)** (`[Resolved in 0c8e87f]`):
  Pins 9 specific outcomes of the heuristic frequency table in `SearchPattern.commonness(of:)` (e.g. `"hello"` anchoring on `'l'`). That makes the test brittle against harmless heuristic tuning; testing invariants (anchor is exact, `nil` when all fold, avoids `0x00` when a non-zero exact byte exists, ties pick earliest) gives the same protection without coupling to magic weights.

- **Redundancy & nondeterminism between [SearchScanTests.swift](../../TwinPanesKit/Tests/TwinPanesCoreTests/SearchScanTests.swift) and [SearcherTests.swift](../../TwinPanesKit/Tests/TwinPanesCoreTests/SearcherTests.swift)** (`[Resolved in 0c8e87f]`):
  - `SearchScanTests.readsOnlyThroughTheSequentialPath` ([L94-L100](../../TwinPanesKit/Tests/TwinPanesCoreTests/SearchScanTests.swift#L94-L100)) and `SearcherTests.ignoresCaseWithoutAnAnchor` ([L46-L50](../../TwinPanesKit/Tests/TwinPanesCoreTests/SearcherTests.swift#L46-L50)) overlap heavily with `SearcherTests.findsAcrossChunkBoundaries` and `SearchScanTests.matchesANaiveSearch`.
  - `SearchScanTests.matchesANaiveSearch` uses `UInt64.random(in: .min ... .max)` ([L33](../../TwinPanesKit/Tests/TwinPanesCoreTests/SearchScanTests.swift#L33)) for 600 iterations on every run; a fixed deterministic seed (plus targeted boundary cases) avoids CI flake while keeping the same coverage.

- **Minor bloat / clutter**:
  - [SandboxProbeTests.swift](../../TwinPanesKit/Tests/SandboxProbeTests/SandboxProbeTests.swift#L52-L61) (`fileProbeNotesACoveringFolderGrant`) (`[Resolved in 0c8e87f]`): runs the full destructive `probeFile` pipeline (2× `clone-stage-replace`, 2× bookmark creation, xattrs, tags, `F_FULLFSYNC`) twice just to test one `coveringFolder` string formatting branch.
  - [BookmarkStoreTests.swift](../../TwinPanesKit/Tests/TwinPanesCoreTests/BookmarkStoreTests.swift#L44-L50) (`noLimitKeepsEverything`) (`[Resolved in 75b3dba]`): writes 12 files and generates 12 security-scoped bookmarks on disk just to assert `limit == nil` doesn't truncate (3–4 items is enough, or fold into `newestFirstAndTrimmedToLimit`).
  - [CloseCoordinatorTests.swift](../../TwinPanesKit/Tests/WorkspaceKitTests/CloseCoordinatorTests.swift#L12), [L105-L113](../../TwinPanesKit/Tests/WorkspaceKitTests/CloseCoordinatorTests.swift#L105-L113) (`[Resolved in 99e7623]`): has an unused `var prompts: [String] = []` property, and `layoutsAreIndependent` doesn't exercise `CloseCoordinator` at all (checking that two unrelated `MainFrameLayout` instances don't share `zoomedItemID` is tautological).
  - [HexViewTests.swift](../../TwinPanesKit/Tests/HexViewKitTests/HexViewTests.swift#L1-L29) (`[Resolved in 35c6c61, 46ffaa9]`): contains only two unrelated tests (`partitioningIndex` and `InspectorView`), neither of which touches `HexView` — better folded into `HexModelTests` / an `InspectorViewTests` file.
