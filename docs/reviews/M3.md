### 1. Plan vs. Implementation Gaps

- **Close prompt not exercised in smoke test** (`[Resolved in f78dd34]`, [SmokeTest+Editing.swift](../../TwinPanes/SmokeTest+Editing.swift#L76-L81)): Plan commit 9 called for verifying *"the close prompt offers Discard"*, but the smoke test only checks `!hex.canSave` and `dirtySessions.count == 1`, then calls `hex.discardChanges()` directly. `AppDelegate.askToSave` is completely untested.
- **UI Find / Find All not driven in editing smoke test** (`[Resolved in f78dd34]`, [SmokeTest+Editing.swift](../../TwinPanes/SmokeTest+Editing.swift#L65-L67), [L100-L124](../../TwinPanes/SmokeTest+Editing.swift#L100-L124)): Plan commit 9 specified *"check that Find finds the typed bytes"* and *"edit while a Find All runs over 4 GiB, printing the frame times and checking that the edit completes before the search does"*. The smoke test calls `Searcher(source: snapshot)` directly instead of driving the editor's Find bar (`⌘F` / `⌘G` / Find All), does not measure frame times, and only logs `(the search had already finished)` without asserting overlap (sleeping 50 ms + waiting for prefetch before typing lets a fast sparse scan finish early).
- **Cursor-move / column-switch coalescing rule not enforced** (`[Resolved in c7206b0]`, [HexEditorItem+Editing.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorItem+Editing.swift#L40-L46)): The plan specifies *"Moving the cursor, switching column or pausing for 2 s starts a new entry."* Currently `lastTyping` is never cleared on cursor navigation or `Tab`, so moving away and returning to the same offset (or pressing `Tab` twice) within 2 s still coalesces into the prior undo step.
- **Minor copy drift** (`[Resolved in 1427c10]`): Plan says `"Modified · saving comes in M3b"`; [HexEditorItem.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorItem.swift#L69) renders `"Modified (saving comes in M3b)"`.

### 2. Implementation Bugs & Deficiencies

#### High / Functional Bugs
1. **Stale `Find All` results get cached and hijack the cursor after an edit during search** (`[Resolved in 4ca0a6e]`, [HexEditorViewController+Find.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController+Find.swift#L101-L117), [L195-L201](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController+Find.swift#L195-L201)):
   - If the user edits while `findAll()` is running, `bytesChanged()` clears `allMatches` and `highlights`. When the background search finishes on the old snapshot, `done(value)` writes the pre-edit matches back into `self.allMatches` and `hexView.highlights` and calls `self.step(...)`, moving the cursor away from what the user is typing.
   - Worse, because `self.allMatches` is now populated with stale pre-edit ranges, the next `⌘G` hits the cached fast path at [line 69](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController+Find.swift#L69-L71) and steps through stale pre-edit offsets instead of searching the edited file.
2. **Discard alert breaks Escape key and misses destructive styling** (`[Resolved in 5fdfa43]`, [AppDelegate.swift](../../TwinPanes/AppDelegate.swift#L264-L273)):
   - When `canSave == false`, `"Cancel"` is added as button 0 (the default button), so AppKit binds Return (`"\r"`) to it instead of Escape (`"\u{1b}"`). Pressing Esc on the Discard sheet will not cancel it.
   - `"Discard Changes"` should set `hasDestructiveAction = true`.
3. **Hex typing silently fails on uncached bytes** (`[Resolved in cb9a986]`, [HexView+Editing.swift](../../TwinPanesKit/Sources/HexViewKit/HexView+Editing.swift#L31-L33)):
   - Hex mode requires `dataSource.cachedBytes(offset..<(offset + 1))?.first` to preserve the other nibble. If the cursor's page isn't cached yet (e.g. typing right after `⌘L` on a large file, or after scrolling the cursor off-screen and evicting its page), hex typing silently beeps without triggering a prefetch or fallback read, whereas text-column typing succeeds. (`SmokeTest+Editing` had to manually `display()` and spin-wait for `cachedBytes` to work around this.)
4. **Undo coalescing ignores manual cursor moves / column toggles back to the same offset** (`[Resolved in c7206b0]`, [HexEditorItem+Editing.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorItem+Editing.swift#L40-L46)):
   - Because `lastTyping` is only cleared on `undo`/`redo`/`discardChanges`, moving away and clicking back (or pressing `Tab` twice to drop a pending nibble) within 2 s still merges with the previous undo entry.

#### Medium / Reliability & Error-Handling Deficiencies
5. **`AddBuffer` mutex held across blocking `pwrite` syscall + error-handling gaps** (`[Resolved in a84b087]`, [AddBuffer.swift](../../TwinPanesKit/Sources/TwinPanesCore/AddBuffer.swift#L39-L41), [L61-L75](../../TwinPanesKit/Sources/TwinPanesCore/AddBuffer.swift#L61-L75)):
   - `append` holds `state.withLock` across `pwrite`, stalling any background `Searcher` calling `add.read`/`length` during disk I/O.
   - `createDirectory` catch hardcodes `errno: EACCES` instead of the real POSIX error (`ENOSPC`, `EROFS`, etc.).
   - `pwrite` returning `0` would spin forever (`done += 0`); check `n <= 0`.
   - `AddBufferError` does not conform to `CustomStringConvertible`, so [HexEditorItem+Editing.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorItem+Editing.swift#L36) prints raw Swift enum text (`writeFailed(offset: 0, errno: 28)`) to the status bar.
   - `AddBuffer` defines its own `pageSize` ([line 15](../../TwinPanesKit/Sources/TwinPanesCore/AddBuffer.swift#L15)) but delegates page math to `ByteSource.pages(covering:)` ([lines 99, 115](../../TwinPanesKit/Sources/TwinPanesCore/AddBuffer.swift#L99)) — a latent corruption bug if those constants ever diverge.
6. **`EditSnapshot.prefetch` gaps** (`[Resolved in 01c6023]`, [EditBuffer.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditBuffer.swift#L58-L91)):
   - Evicted `AddBuffer` loads run on `DispatchQueue.global(qos: .userInitiated)` with no cancellation/superseding and unbounded concurrency; even when `original.prefetch` was superseded (completes with `nil`), `loadAdds()` still runs for the stale viewport.
   - When `originals` is empty (a fully overwritten screen), an earlier in-flight `original.prefetch` is never superseded.
7. **`discardChanges()` doesn't refresh the editor view** (`[Resolved in c7206b0]`, [HexEditorItem+Editing.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorItem+Editing.swift#L16-L21)):
   - Resets `buffer` and `undoStack` and fires `onChange`, but never calls `controller.bytesChanged()` or clears `hexView.pendingNibble`. Any caller that discards while the tab stays open (including [SmokeTest+Editing.swift](../../TwinPanes/SmokeTest+Editing.swift#L80)) leaves stale highlights/display/inspector state until another event redraws.

#### Low / Polish
8. **Double status/inspector update per keystroke** (`[Resolved in cb9a986]`): [HexEditorViewController+Editing.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController+Editing.swift#L17) calls `bytesChanged()` inside the delegate before [HexView+Editing.swift](../../TwinPanesKit/Sources/HexViewKit/HexView+Editing.swift#L56-L58) moves the cursor and calls `selectionChanged(reveal: true)` (which updates status and inspector a second time, and also fires `hexViewSelectionDidChange` before `pendingNibble = nibble`).
9. **Control characters accepted by `TextEncoding.byte(for:)`** (`[Resolved in cb9a986]`, [HexViewOptions.swift](../../TwinPanesKit/Sources/HexViewKit/HexViewOptions.swift#L32-L40)): `character(for:)` treats `0x00..0x1F`, `0x7F`, and Latin-1 `0x80..0x9F` as non-printable, whereas `byte(for:)` accepts them if delivered to `insertText(_:)`. Also multi-character `insertText` stops mid-string on the first bad character, leaving a partial edit.
10. **Missing `reserveCapacity` in `EditSnapshot.read` / `readSequential` / `cachedBytes`** (`[Resolved in 01c6023]`, [EditBuffer.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditBuffer.swift#L20-L54)).

### 4. Overall Architecture Assessment

#### What Works Well
- **Module boundaries**: `TwinPanesCore` stays pure Swift (no AppKit), `HexViewKit` stays independent of `EditBuffer` via `HexViewDataSource`/`HexViewDelegate`, and `EditorKit` composes them cleanly.
- **Persistent join-based AVL `PieceTree`**: The Blelloch join/split implementation in [PieceTree.swift](../../TwinPanesKit/Sources/TwinPanesCore/PieceTree.swift) is mathematically sound, deterministic, and already implements `insert`/`remove` with bidirectional neighbour merging — M8 won't need to rework the tree.
- **`EditSnapshot: ByteReading` + version-identity dirty state**: Routing `Searcher`, `readForCopy`, and `Save Selection` through `EditSnapshot` cleanly decouples background work from UI edits, and `isSameVersion(as: openedTree)` generalizes cleanly to `savedTree` in M3b.

#### Architectural Friction Points for M3b / M8 / M10
1. **Eager `AddBuffer` creation on open** (`[Resolved in M3b/M3c]`, [EditBuffer.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditBuffer.swift#L129)): Every opened hex tab creates a temp folder and opens a writable file descriptor even for pure read-only viewing. Creating the backing file lazily on first `append` avoids disk churn, FD consumption, and empty orphan temp directories if the app terminates unexpectedly.
2. **M3b multi-view `EditorSession` ownership of `UndoStack`** (`[Resolved in M3b/M3c]`): Decision D-c moved `UndoStack` onto `HexEditorItem` so entries can store `selection`. Once M3b introduces `EditorSession` (multiple tabs/windows over one file), `UndoStack` must move to `EditorSession` (shared history across views) and `EditBuffer` / `EditorSession` will need a multi-observer notification mechanism so sibling views redraw, update dirty badges, and invalidate find results when another view edits or undoes.
3. **`EditSnapshot.prefetch` assumes overwrite-only monotonicity** (`[Deferred to M8]`, [EditBuffer.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditBuffer.swift#L86-L87)): Prefetching `first.offset..<(last.offset + last.length)` works for overwrite-only, but once M8 introduces delete, a single large deletion between two visible pieces will prefetch the entire deleted span from disk. Prefetching per original span (or merging only nearby spans) avoids that cliff.
4. **`EditSnapshot.readSequential` fragmentation cliff** (`[Deferred to M8]`, [EditBuffer.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditBuffer.swift#L30-L41)): Issuing one `F_NOCACHE` `pread` per `.original` piece and reading `.add` pieces through `AddBuffer`'s LRU cache works for a few edits, but degrades sharply on a heavily edited file (many scattered 1-byte edits in a 1 MiB search/save chunk) and thrashes `AddBuffer`'s 64-page cache during full-file scans. M3b saving and M8 heavy editing will want an uncached sequential read on `AddBuffer` and chunked/coalesced reads for fragmented spans.
5. **Unenforced actor isolation on `EditBuffer`** (`[Open — logged in PLAN.md §9]`): [EditBuffer.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditBuffer.swift#L118) documents *"Not thread-safe; it belongs to the editor's actor"*, but the type itself has no `@MainActor` or actor boundary, leaving thread-safety enforcement purely to convention.

### Executive Summary

**What is working well:**
- The module layering (`EditorSession` / `SessionRegistry` / `SavePlan` / `Saver` / `FileSystem` in Foundation-only `TwinPanesCore`, presentation-only `HexEditorItem`) is clean and easy to reason about.
- `SavePlan`'s side-by-side piece diff + 200×80 seeded fuzz test, `JournalFormat`'s CRC32C truncation/bit-flip fuzz, and the 4 GiB clone-and-patch save (~70 ms) are solid foundations.
- Lazy folder/clone creation on first edit keeps read-only viewing side-effect-free.

**Where the serious risks sit:**
1. **Crash recovery & Strategy B rollback have real data-corruption holes** — notably `SaveJournal.rollBackIfNeeded` running *before* `SecurityScope` starts and deleting `save-journal.bin` unconditionally in `defer`, plus `AddBuffer` bypassing `FileSystem` and missing bounds checks in journal replay.
2. **In-flight saves race with `reloadDiscardingEdits()`, `revert()`, tab/window `close()`, and external writes** (TOCTOU between `SavePlan`'s stat and `Saver.save`), risking silent merges or deleting Strategy B's `save-journal.bin` mid-write.
3. **External changes break `HexView` layout/selection when file length changes** and silently drop the prompt on hidden tabs or while another sheet is up.
4. **Several tests give false confidence** (the `savingRaisesNothing` watcher test attaches its observer *after* the saves; `JournalFaultTests` does not actually enforce the power-loss durability bound or check disk on rollback; and `EditorSessionSavingTests` violates the Xcode 16/26/27 rule against capturing `Mutex` locals in `Task`).
5. **M3c is still incomplete** (steps 13–14: `SF_DATALESS`, subprocess crash smoke test, `applicationWillResignActive` flush), while `README.md` already presents M3c as shipped and `docs/PLAN.md` has internal contradictions.

### 1. Findings by Severity

#### Critical

1. **Strategy B rollback runs before `SecurityScope` activates and deletes `save-journal.bin` on failure** (`[Resolved in 273378f]`)
   - [EditorSession.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession.swift#L113-L125), [SaveJournal.swift](../../TwinPanesKit/Sources/TwinPanesCore/SaveJournal.swift#L65-L84), [Saver.swift](../../TwinPanesKit/Sources/TwinPanesCore/Saver.swift#L99-L101)
   - `EditorSession.init(recovering:)` runs `SaveJournal.rollBackIfNeeded` *before* decoding `manifest.json`, resolving `manifest.bookmark`, and activating `SecurityScope`. In the sandbox, `FileIdentity` and `openForWriting` fail with `EPERM`; `defer { fileSystem.removeItem(at: journal) }` (`SaveJournal.swift:71`) deletes `save-journal.bin` anyway, and `_ = try?` swallows the error. The partially written hard-linked file stays corrupted permanently. Also uses the stale stored path rather than the bookmark-resolved URL if the file moved.

2. **TOCTOU between `SavePlan` identity check and `Saver.save` + unconditional `ftruncate` in Strategy B** (`[Open — Step 2]`)
   - [EditorSession+Saving.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession+Saving.swift#L105-L125), [Saver.swift](../../TwinPanesKit/Sources/TwinPanesCore/Saver.swift#L50-L78), [Saver.swift](../../TwinPanesKit/Sources/TwinPanesCore/Saver.swift#L83-L104), [Saver.swift](../../TwinPanesKit/Sources/TwinPanesCore/Saver.swift#L149)
   - `performSave()` stats `url` on `@MainActor` to build a ranged `SavePlan`, then `Saver.save` stats `url` again off-main and never verifies it still matches the identity the ranged plan was built for. An external write in that gap produces a silent corrupted merge (and `savedTree` advances as if disk matched it). In Strategy B, `write()` also calls `truncate(..., to: plan.length)` even though `SaveJournal` does not back up or restore length.

3. **In-flight saves race with `reloadDiscardingEdits()`, `revert()`, and `close()` (tab/window)** (`[Resolved in 5c97449]`)
   - [EditorSession+Saving.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession+Saving.swift#L44-L59), [EditorSession+Saving.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession+Saving.swift#L102-L130), [EditorSession+Watching.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession+Watching.swift#L45-L51), [EditorSession.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession.swift#L197-L203), [EditorSession+Folder.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession+Folder.swift#L66-L73), [HexEditorItem.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorItem.swift#L108-L114)
   - Reloading or reverting during an active save lets the finishing save overwrite disk with stale bytes and set `savedTree = version` from the pre-reload buffer (corrupting later `SavePlan` diffs) or append an old `replaceCount` to a brand-new journal.
   - Closing a tab (`⌘W`) or window (`⇧⌘W`) does not wait for `finishSaving()` (only quit does): `willClose()` calls `session.close()`, deleting the session folder and Strategy B's `save-journal.bin` while `Saver.saveInPlace` is writing.

4. **Power-loss ordering gap between `AddBuffer` and `SessionJournal` + unvalidated `JournalFormat` replay** (`[Open — Step 4]`)
   - [SessionJournal.swift](../../TwinPanesKit/Sources/TwinPanesCore/SessionJournal.swift#L51-L72), [Journal.swift](../../TwinPanesKit/Sources/TwinPanesCore/Journal.swift#L65-L83), [Journal.swift](../../TwinPanesKit/Sources/TwinPanesCore/Journal.swift#L102-L123), [AddBuffer.swift](../../TwinPanesKit/Sources/TwinPanesCore/AddBuffer.swift#L103-L140)
   - `AddBuffer` writes outside `FileSystem` and only `F_FULLFSYNC`s every ~1 s; a power loss can persist `journal.bin` records referencing `.add` ranges beyond `AddBuffer.length`. `JournalFormat.replay` never validates `.add` offsets against `add.length`, `.original` against `originalLength`, or `range.upperBound <= currentTree.length`.
   - `JournalFormat.parse` also accepts `piece.length == 0` (which hits `precondition(piece.length > 0)` in `PieceTree.appending` and crashes on every launch) and unknown source tags (`> 1`).
   - Saving `< 1 s` after typing does not flush `journal.bin` before `Saver` runs; power loss between target replace and `recordSaved` recovers the pre-edit clone as clean.

5. **`HexView` never updates layout or clamps selection when an external change alters file length** (`[Resolved in 4b4537d]`)
   - [HexEditorItem+Editing.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorItem+Editing.swift#L71-L90), [HexEditorViewController+Editing.swift](../../TwinPanesKit/Sources/EditorKit/HexEditorViewController+Editing.swift#L41-L46), [HexView.swift](../../TwinPanesKit/Sources/HexViewKit/HexView.swift#L137-L145)
   - `reloadFromDisk()` replaces `buffer` and notifies `.edited`. `bytesChanged()` only sets `hexView.needsDisplay = true`, leaving `hexView.layout.length` and `hexView.selection` stale. Shrinking causes repeated `ByteSourceError.truncated` placeholders; growing makes appended bytes unreachable. Violates M3c D-c (*"selection clamped to the new length"*).
   - Also, on first edit after an unseen external change (`protectBeforeFirstEdit` reloads at [EditorSession+Folder.swift:11](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession+Folder.swift#L11)), `HexView.type(_:)` already read the old file's byte to merge the nibble, and `applyingTypingEdit` suppresses `bytesChanged()` — silently overwriting the reloaded file with a hybrid byte or leaving a stale view.

6. **Symlink handling in Strategy A copy fallback mutates the live target in place (or throws `ENOENT`)** (`[Open — Step 2]`)
   - [FileSystem.swift](../../TwinPanesKit/Sources/TwinPanesCore/FileSystem.swift#L56-L64), [Saver.swift](../../TwinPanesKit/Sources/TwinPanesCore/Saver.swift#L60-L77)
   - `FileManager.copyItem` copies the symlink itself into `itemReplacementDirectory`. An absolute symlink is then opened through `openForWriting(staged)` and **mutated in place** before `replaceItem`, defeating Strategy A atomicity; a relative symlink becomes dangling (`ENOENT`).

7. **Missing `applicationWillResignActive` journal flush (violates M3c D-e)** (`[Open — Step 4]`)
   - [AppDelegate.swift](../../TwinPanes/AppDelegate.swift), [SessionJournal.swift](../../TwinPanesKit/Sources/TwinPanesCore/SessionJournal.swift#L67-L72)
   - `EditorSession` has no public flush hook and `AppDelegate` does not flush journals on deactivation; App Nap or sleep before the 1 s timer can lose edits.

#### High

8. **`journalSaved` updates `manifest.json` even when `recordSaved` fails (or `journal == nil`) and without syncing `manifest.json`** (`[Open — Step 4]`)
   - [EditorSession+Saving.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession+Saving.swift#L63-L71), [SessionFolder.swift](../../TwinPanesKit/Sources/TwinPanesCore/SessionFolder.swift#L73-L75)
   - If `recordSaved` throws (or `journal` was previously dropped), `updateManifest` still writes the new post-save identity while `journal.bin` lacks `.saved(count)`. After recovery, `diskMatchesSaved` is `true` against the wrong `savedTree`, causing `SavePlan` to skip dirty ranges (silent corruption). Conversely, a power loss between `recordSaved` and unsynced `updateManifest` leaves `.saved(N)` paired with the old path/identity.

9. **Blocking `F_FULLFSYNC` on `@MainActor` + `SessionJournal` file descriptor leak** (`[Open — Step 4]`)
   - [SessionJournal.swift](../../TwinPanesKit/Sources/TwinPanesCore/SessionJournal.swift#L7-L8), [SessionJournal.swift](../../TwinPanesKit/Sources/TwinPanesCore/SessionJournal.swift#L67-L99), [EditorSession.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession.swift#L156-L161)
   - `SessionJournal.flush()` runs `add.sync()` and `fileSystem.fullSync()` synchronously on `@MainActor` every ~1 s while typing and on every save/close, stalling UI/120 Hz scrolling (violating PLAN.md §3).
   - `SessionJournal` has no `deinit`, and `EditorSession.deinit` doesn't close `journal`, leaking the fd whenever `journal = nil` on error or a session deallocates without `close()`.

10. **Recovery bugs: destructive `AddBuffer.deinit`, ignored `.closed` record, permanent orphans, clean/reverted crashes recovered dirty, and Strategy B post-rollback `mtime` lockout** (`[Partially resolved: Strategy B mtime in 273378f; remaining open — Step 5]`)
    - [EditorSession.swift](../../TwinPanesKit/Sources/TwinPanesCore/EditorSession.swift#L115-L145), [AddBuffer.swift](../../TwinPanesKit/Sources/TwinPanesCore/AddBuffer.swift#L69-L97), [SessionFolder.swift](../../TwinPanesKit/Sources/TwinPanesCore/SessionFolder.swift#L89-L105), [Journal.swift](../../TwinPanesKit/Sources/TwinPanesCore/Journal.swift#L102-L123)
    - **Destructive unwind:** If `SessionJournal(reopening:)` throws after `AddBuffer(reopening:)` succeeds, `AddBuffer.deinit` deletes the recovered `add-buffer` folder from disk.
    - **Ignored `.closed` record:** Crash between `journal.close()` (writing `.closed`) and `folder.markClosed()` causes `sweep` to recover the closed session and append new records after `.closed`.
    - **Permanent orphans:** Crash after `SessionFolder.create` (`manifest.json`) before `original.clone` / `AddBuffer` exist leaves a folder `sweep` returns forever and `AppDelegate` skips forever.
